BOT DATA INFRASTRUCTURE · PRIVATE OPERATING VIEW

How LocalLink bots receive evidence, reason, use tools and remain controlled

This workflow separates the authoritative marketplace from the agent runtime. Bots never become the source of truth. Data is classified, permission-filtered, retrieved with provenance, passed through policy gates, and observed from request to human-approved action.

Core architectural rule

Business records stay in authoritative services. Agent memory stores working context and approved knowledge references, not unrestricted copies of customer, credential, address or financial data. Every consequential tool call is policy-checked, approval-gated when required, idempotent and auditable.

BOT RUN: request → authorization → retrieval → planning → tools → validation → approval → command → trace
Data-classification boundary
  • Public: published listings and approved policy text
  • Internal: operations metrics and moderation queues
  • Restricted: addresses, credentials, disputes and private messages
  • Financial: provider/payment references and ledger events
Non-negotiable prohibitions
  • No direct agent writes to authoritative tables
  • No raw secrets, card data or unrestricted PII in prompts
  • No arbitrary MCP server connected to production
  • No agent-enforced sanctions, payouts or refunds
  • No memory promotion without evidence and approval
1. Systems of record

Identity, catalog, engagement, moderation, audit and future finance remain deterministic.

2. Data plane

CDC/outbox events, object storage, approved corpus, metadata and vector indexes.

3. Agent control plane

Router, scoped context builder, durable workflow state, budgets and policy engine.

4. Tool plane

Allowlisted MCP/tool gateway, per-tool schemas, short-lived credentials and sandboxing.

5. Assurance plane

Tracing, evaluations, red-team tests, audit records, alerts, rollback and human review.

Research-backed design basis

MCP architecture

Host-controlled clients maintain one-to-one server connections and preserve isolation between specialized servers.

MCP security considerations

Production MCP requires rigorous validation, restricted execution and hardened trust boundaries.

Durable agent workflows

Deterministic and model-driven steps can coexist with persistence and human intervention.

GenAI observability conventions

Standardized spans, metrics and events can cover agents, model calls, tools, retrieval and MCP.

PostgreSQL vector retrieval

Approved embeddings can remain beside relational metadata, access controls and transactional records.

OWASP GenAI risks

Prompt injection, sensitive disclosure, excessive agency and unsafe tool behavior require layered controls.
